# v0.9 下一集播放等待

## 目标

一集播完直接播下一集，不出现倒计时界面。设置里的「自动播放倒计时」改成三态：

| 取值 | 含义 |
| --- | --- |
| `0` | 不等待，直接播下一集 |
| `-1` | 一直等待，停在下一集界面直到用户选择 |
| 其他 | 倒计时多少毫秒后自动播下一集 |

默认值从 7000 毫秒改成 0。

## 现状与根因

一集播完时 `PlaybackController.itemComplete()` 决定是弹下一集界面还是直接播下一集：

- 「还在看吗」开启且追踪器要求弹时，弹「还在看吗」界面。
- 否则下一集界面开启时，弹下一集界面，界面里的倒计时由 `UserPreferences.nextUpTimeout` 控制。
- 倒计时结束就自动播下一集；`nextUpTimeout` 为 0 时倒计时被禁用，界面一直停着等用户选。

所以现在的 0 是「一直等待」，与需求要的语义正好相反，而且默认值 7000 让每一集播完都要先停 7 秒。

## 执行步骤

1. `NextUpBehavior.kt` 增加 `NEXTUP_TIMER_NO_WAIT = 0`，把 `NEXTUP_TIMER_DISABLED` 改成 -1（计时器禁用＝一直等待，名字与含义都不变）。
2. `UserPreferences.nextUpTimeout` 的默认值改成 `NEXTUP_TIMER_NO_WAIT`。
3. 新增 `ui/playback/nextup/NextUpDecision.kt`，把判断拆成两个纯函数：`timeoutAction` 决定下一集界面是立即播、倒计时还是等用户；`nextItemAction` 决定一集播完时弹「还在看吗」、弹下一集界面还是直接播下一集。
4. `PlaybackController.itemComplete()` 改成先算 `nextItemAction`，判定为直接播下一集时走原来的 `next()`，其余保持原逻辑推进队列下标并弹对应界面。
5. `NextUpOverlay` 的倒计时按 `timeoutAction` 分派。
6. 设置界面：滑块最小值改成 -1000（步长 1000），标签按状态显示「无限」「不等待」或秒数；新增字符串 `pref_next_up_timeout_no_wait`。
7. 偏好迁移 `toVersion = 10`：用户显式存过的 0（老语义＝一直等待）改写成 -1，没存过的用户拿新默认值 0。

## 顺带修掉的旧缺陷

原代码在「还在看吗」开启但追踪器这次不要求弹、同时下一集界面被关闭时，会推进队列下标后直接结束播放，下一集永远不播。
现在这种情况与下一集界面关闭时一样，直接播下一集。

## 最终方案

| 场景 | 行为 |
| --- | --- |
| 默认（一集播完） | 直接播下一集，不出现下一集界面 |
| 倒计时设为 7 秒 | 弹下一集界面，倒计时结束自动播下一集 |
| 倒计时设为 -1 | 弹下一集界面，一直停着等用户选择 |
| 「还在看吗」开启且追踪器要求弹 | 优先弹「还在看吗」，与倒计时设置无关 |
| 播放的是预告片 | 直接播下一集，不弹任何界面 |

## 附录

### 备选方案与取舍

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| 在下一集界面里判断「不等待」并立即跳下一集 | 界面还是会闪一下 | 未采用，需求要求不出现倒计时界面 |
| 用单独的开关键表示「一直等待」 | 滑块之外再加一项 | 未采用，滑块最小值改成 -1 就能选到，改动更小 |
| 迁移时把老版本存下的 0 改成新的默认值 | 老用户直接变成不等待 | 未采用，显式选过「无限」的用户保留自己的选择 |

### 偏好迁移版本号

迁移用的版本号 10 接在上游 v0.20.0 的迁移 9 后面。上游之后如果也用 10，合并上游时要重新编号，
否则已经升级到 10 的用户会跳过上游那条迁移。

### 下一集界面在「不等待」时不再出现

「下一集行为」设置（显示条目信息、隐藏条目信息、不显示）在倒计时为 0 时没有可见效果，
因为整个下一集界面都不会出现。本次不动这个设置界面。
