# v0.4 24 小时制

## 目标

APP 内所有时间显示固定为 24 小时制，格式为补零的 `HH:mm`。不跟随投影仪系统的 12/24 小时设置，不新增设置项。时长显示、日期部分、相对日期显示保持原样。

## 背景

改动前的时间显示分散在三处，各自带一套 12/24 判断：

| 来源 | 位置 | 改动前行为 |
| --- | --- | --- |
| Kotlin 统一入口 | `util/DateTimeExtensions.kt` 的 `getTimeFormatter()` 与 `getDateFormatter()`，被节目卡、EPG 时间轴、节目单弹窗、播放控制条「结束于」、详情页、录制弹窗等 12 处调用 | 跟随系统 12/24 设置，中文环境输出 `下午4:42` |
| Compose 时钟 | `ui/composable/time.kt` 的 `rememberCurrentTime()`，用于首页、详情页、待机页的 `ToolbarClock` | 跟随系统 12/24 设置，投影仪上显示 `4:20` |
| XML `TextClock` | `res/layout/clock_user_bug.xml`（经 `ClockUserView` 进入首页、详情页、播放页等界面）、`res/layout/overlay_tv_guide.xml`（经 `OverlayTvGuideBinding` 进入播放页直播节目单） | 布局里写死 `format12Hour="h:mm"` 与 `format24Hour="k:mm"`，由系统在两者间二选一 |

另有三处绕过统一入口直接调用 `DateTimeFormatter.ofLocalizedTime(FormatStyle.SHORT)`，也需要一并改。

## 执行步骤

1. 在 `res/values/strings.xml` 增加 `<string name="time_format_24h" translatable="false">HH:mm</string>`，作为全 APP 唯一的时间格式来源，Kotlin 与 XML 共用。
2. 在 `util/DateTimeExtensions.kt` 增加 `Context.getTimePattern()` 读取该字符串。把 `getTimeFormatter()` 改为按该模式构造并删除 `FormatStyle` 参数。把 `getDateFormatter()` 改为「本地化日期 + 空格 + 24 小时时间」的组合。
3. 在 `ui/composable/time.kt` 的 `rememberCurrentTime()` 中删除 `format12` 与 `format24` 两个参数以及 `DateFormat.is24HourFormat(context)` 分支，格式改用 `context.getTimePattern()`。
4. 把 `clock_user_bug.xml` 与 `overlay_tv_guide.xml` 中两个 `TextClock` 的 `format12Hour` 与 `format24Hour` 都改为 `@string/time_format_24h`。
5. 把 `ui/browsing/composable/inforow/BaseItemInfoRow.kt` 与 `ui/settings/screen/authentication/SettingsAuthenticationServerScreen.kt` 中三处 `ofLocalizedTime` 调用改为 `context.getTimeFormatter()`。
6. 引入 Robolectric 依赖并开启 `isIncludeAndroidResources`，补齐 JDK 17 以上必需的 JVM 参数，让 JUnit 4 的 Robolectric 用例与现有 Kotest 用例在同一个 `testDebugUnitTest` 任务里共存。
7. 新增 `app/src/test/kotlin/util/TimeFormatTests.kt`，覆盖格式来源、时间格式化、日期加时间、与系统设置无关、XML 接线、渲染语义与时长回归。
8. 跑通全部单元测试后打包安装到投影仪。

## 最终方案

| 场景 | 行为 |
| --- | --- |
| 首页、详情页、待机页的 Compose 时钟 | 固定 `HH:mm`，例如 `16:42`、`09:05`、`00:00` |
| 首页、详情页、播放页、直播节目单右上角的 XML 时钟 | 固定 `HH:mm`，与系统 12/24 设置无关 |
| 节目卡、EPG 时间轴、节目单弹窗、播放控制条「结束于」等 | 固定 `HH:mm` |
| 日期加时间的整串显示 | 本地化日期 + 空格 + `HH:mm`，例如 `2026/11/12 16:42` |
| 时长显示 | 不变，例如 `21:43` |
| 相对日期 | 不变，仍为「今天」「明天」 |

## 自动化验证

验证方式为 Robolectric 单元测试，在 JVM 里用真实的 Android 资源与框架类断言，不需要连接投影仪或模拟器。

用例清单（`app/src/test/kotlin/util/TimeFormatTests.kt`）：

| 用例 | 断言内容 |
| --- | --- |
| `timePatternIs24Hour` | `R.string.time_format_24h` 与 `getTimePattern()` 都是 `HH:mm` |
| `timeFormatterRenders24HourWithZeroPadding` | `getTimeFormatter()` 对 00:00、09:05、16:42、23:59 分别输出 `00:00`、`09:05`、`16:42`、`23:59` |

| `xmlTextClocksUse24HourPattern` | `clock_user_bug.xml` 的 `clock` 与 `overlay_tv_guide.xml` 的 `textClock2`，`getFormat12Hour()` 与 `getFormat24Hour()` 都是 `HH:mm` |

## 附录

### 三处时间来源的排查

- `getTimeFormatter()` 的调用点：`ProgramGridCell`、`ChannelCardView`、`RecordPopup`、`TvManager`、`LiveTvGuideFragment`、`CustomPlaybackOverlayFragment`、`CustomPlaybackTransportControlGlue`、`FullDetailsFragment`、`BaseItemDtoBaseRowItem`、`BaseItemExtensions`。
- `getDateFormatter()` 的调用点：`TimeUtils.getFriendlyDate()` 的回退分支与 `FriendlyDateButton`。
- 直接调用 `ofLocalizedTime` 的调用点：`BaseItemInfoRow` 两处，`SettingsAuthenticationServerScreen` 一处。
- `TimeUtils.formatMillis()` 用的是 `%d:%02d` 这类固定格式，与本次改动无关，时长显示保持不变。
- `getFriendlyDate()` 先返回「今天」「明天」，只有回退分支才会用到日期格式化，相对日期显示不受影响。

### TextClock 的两个属性都要设

AOSP 的 `TextClock.chooseFormat()` 在系统为 12 小时制时取 `mFormat12`，24 小时制时取 `mFormat24`。构造函数在 XML 属性缺失时会把 `mFormat12` 兜底为本地化的 `hm` 模式、`mFormat24` 兜底为 `Hm` 模式，两者都非空。因此只设置其中一个属性，另一条分支仍会走系统本地化格式。两个属性都指向 `@string/time_format_24h` 才能保证与系统设置无关。

### Android 的 java.time 缺少 appendLocalizedDate

`java.time.format.DateTimeFormatterBuilder` 在 Android 上只有 `appendLocalized(FormatStyle, FormatStyle)` 与 `appendLocalized(String)`，没有 OpenJDK 里的 `appendLocalizedDate`、`appendLocalizedTime`、`appendLocalizedDateTime`。所以日期加时间的组合要用 `append(DateTimeFormatter.ofLocalizedDate(style))` 拼接。实测 zh-CN 下结果为 `2026/11/12 16:42`。

### Robolectric 在 JDK 21 下的额外要求

- 必须给单元测试任务加 `--add-opens` 与 `--add-exports`，覆盖 `java.base` 的 `java.lang`、`java.util`、`java.io`、`java.net`、`java.nio`、`java.text`、`java.util.concurrent` 以及 `jdk.internal.access`、`jdk.internal.misc`。缺少 `jdk.internal.access` 时会报 `IllegalAccessException: Failed to interact with raw FileDescriptor internals`。
- 项目现有测试用 Kotest 走 JUnit 5 平台，Robolectric 官方 runner 是 JUnit 4。引入 `junit-vintage-engine` 让两种引擎在同一个 `testDebugUnitTest` 任务里共存，实测互不影响。
- `TextClock` 在 Robolectric 下不会渲染出文本，`getText()` 始终为空，所以断言点定在 `getFormat12Hour()` 与 `getFormat24Hour()`，这正是「与系统设置无关」的决定性证据。
- `android.text.format.DateFormat.format()` 在 Android 上返回 `CharSequence` 而不是 `String`，调用处需要 `toString()`。

### 备选方案与取舍

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| 跟随系统 12/24 设置 | 只在系统为 24 小时制时生效 | 未采用。需求要求固定 24 小时制，投影仪的系统设置不可控 |
| 纯 JVM 单测，不引入 Robolectric | 格式常量放 Kotlin，XML 另存一份字符串资源 | 未采用。XML 接线只能靠人工复核，且两处字面量可能漂移 |
| 新增 androidTest 源集，在模拟器上跑 | 最接近真机行为 | 未采用。需要新增源集与构建配置，模拟器内还要能登录到服务器，端到端断言不稳定 |
| Robolectric 单元测试 | 在 JVM 里用真实 Android 资源与框架类断言 | 采用。一条命令覆盖三处时间来源，不依赖任何设备 |
| 自动化通过后仍安装到投影仪 | 人工只做一次性抽查，不再逐屏走查 | 采用 |

### 实现细节

- `getTimeFormatter()` 去掉 `FormatStyle` 参数后，JVM 签名仍是 `getTimeFormatter(Context)`，12 处 Java 调用点无需改动。
- `getDateFormatter()` 保留 `FormatStyle` 参数，但只作用于日期部分，日期仍按系统 locale 本地化。
- Compose 时钟保留 `android.text.format.DateFormat` 的渲染逻辑，只改格式来源。`DateFormat.format("HH:mm", now)` 与 `DateTimeFormatter.ofPattern("HH:mm")` 输出一致，都是 0 到 23 补零。
- `BaseItemInfoRow` 与 `SettingsAuthenticationServerScreen` 中用 `remember(context)` 缓存 formatter，避免列表滚动时反复解析格式模式。
- 新增字符串带 `translatable="false"`，不需要同步到各语言目录；`strings.xml` 根节点已有 `tools:ignore="MissingTranslation"`。
