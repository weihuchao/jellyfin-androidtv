# 媒体库显示设置崩溃

## 目标

在投影仪上浏览媒体库的子文件夹时，打开右上角齿轮里的「显示设置」会让整个应用退出，需要找到原因并修掉。

## 现象

用户提供的两份 ACRA 崩溃报告，崩溃时间分别是 12:27:45 与 12:28:15，堆栈完全相同：

```text
java.util.NoSuchElementException: Collection contains no element matching the predicate.
```

崩溃前的日志显示请求刚发出：

```text
12:27:45.452 GET http://hare.fe.go/UserViews?includeHidden=false
12:27:45.570 ACRA caught a NoSuchElementException for org.jellyfin.androidtv
```

## 原因

崩溃来自应用自己的代码，是上游的一个缺陷，与定制无关。

`app/src/main/java/org/jellyfin/androidtv/ui/settings/screen/library/helpers.kt` 里的 `rememberUserView` 从用户视图里找出当前条目的视图：

```kotlin
userViewsRepository.views.map { views -> views.first { view -> view.id == itemId } }
```

用户视图来自服务端的 `/UserViews`，那里只有顶层媒体库。用户的媒体库结构是「媒体库」这个 CollectionFolder 下面挂着「电影」「剧集」等普通文件夹，在「电影」里打开显示设置时传下去的 `itemId` 是「电影」这个普通文件夹的 id，它不在用户视图里，`first` 找不到匹配项就抛出这个异常。异常发生在协程里，没人接住，整个应用随之退出。

服务端的用户视图只有一条，可以印证这一点：

| 条目 | id | 类型 | 在用户视图里 |
| --- | --- | --- | --- |
| 媒体库 | 10d4718bf10063d57d1165e0e33f8efb | CollectionFolder | 是 |
| 电影 | f20f4c66-6bc7-6481-09a2-5010ca40b561 | Folder | 否 |

四个调用方都是「显示设置」下的页面：显示方式、图片类型、图片大小、网格样式。

## 修复

`first` 改成 `firstOrNull`，找不到视图时返回 null，页面照常打开，只是没有标题。

返回类型本来就是 `BaseItemDto?`，四个调用方也都用 `userView?.` 取值，`UserViewsRepository.isSupported`、`allowViewSelection`、`allowGridView` 对 null 的判断同样安全，所以不需要改别的地方。

## 验证

122 个单元测试全部通过，release 包构建通过。崩溃需要手动复现：进入「媒体库」下的「电影」，点右上角齿轮进「显示设置」。

## 附录

### 从混淆的堆栈定位到源码

release 包的堆栈只有 R8 混淆后的类名，`app/build/outputs/mapping/release/mapping.txt` 里能反查回原始名字：

| 混淆名 | 原始名字 |
| --- | --- |
| kw1 | org.jellyfin.androidtv.ui.settings.screen.library.HelpersKt$rememberUserView$lambda$0$$inlined$map$1$2 |
| x11 | kotlinx.coroutines.DispatchedTask |
| jc | androidx.compose.ui.platform.AndroidUiDispatcher |

从 `map` 的 lambda 和 `DispatchedTask` 可以判断异常出在协程里的集合操作上，再顺着 `rememberUserView` 的调用方就找到了 `first`。

### 同类写法

应用里还有几处 `first` 与 `first {}`：作用于 Flow 的 `first` 与 `first {}` 取的是 Flow 的值，不会因为集合为空而抛异常；`HomeRowsFragment` 里的 `userRepository.currentUser.filterNotNull().first()` 在没有用户时才会抛，与本次无关；外部播放器取 `externalSubtitles.first()` 只在用 VLC 或 Vimu 播放时才走到，也与本次无关。
