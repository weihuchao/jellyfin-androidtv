# v0.2 内置服务器地址

## 目标

定制版本内置默认服务器地址 `http://hare.fe.go`，投影仪上开箱即用，用户不必用遥控器敲地址。

## 背景

官方客户端没有「内置地址」的概念，换设备或清空数据后都要在「输入服务器地址」界面手动输入。投影仪场景下这一步体验很差，是本次定制要消除的主要摩擦点。

## 执行步骤

1. 新增常量 `org.jellyfin.androidtv.constant.ServerAddress.DEFAULT`，值为 `http://hare.fe.go`。
2. `StartupActivity` 在没有已保存服务器时，先尝试连接内置地址：连接成功进入该服务器的用户选择界面，连接失败弹出提示并回退到服务器选择界面。
3. `ServerAddFragment` 的手动输入入口把内置地址预填到地址框，用户可修改后连接。
4. 打包、安装到投影仪，用全新安装的模拟器验证成功与失败两条路径。

## 最终方案

| 场景 | 行为 |
| --- | --- |
| 启动时没有已保存的服务器 | 自动连接 `http://hare.fe.go` |
| 自动连接失败 | Toast 列出尝试过的地址与失败原因，随后进入服务器选择界面 |
| 已保存过服务器 | 维持官方行为，直接进入该服务器（内置地址自动连接成功后会保存下来） |
| 手动输入服务器地址 | 地址框预填 `http://hare.fe.go` |

改动清单：

- `app/src/main/java/org/jellyfin/androidtv/constant/ServerAddress.kt`（新增）
- `app/src/main/java/org/jellyfin/androidtv/ui/startup/StartupActivity.kt`
- `app/src/main/java/org/jellyfin/androidtv/ui/startup/fragment/ServerAddFragment.kt`

## 构建与安装

```shell
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@21/21.0.13.0.3/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
./gradlew assembleRelease -Pjellyfin.version=0.20.0-seamless-v0.2
adb -s 192.168.55.80:5555 install -r app/build/outputs/apk/release/jellyfin-androidtv-v0.20.0-seamless-v0.2-release.apk
```

签名配置放在 `~/.gradle/gradle.properties`，私钥在仓库外的 `secret/jellyfin-tv/`，不入库。

## 附录

### 备选方案与取舍

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A 启动时自动连接 | 没有已保存服务器时直接连内置地址 | 采用。开箱即用，收益最大 |
| B 仅预填输入框 | 地址框默认填入内置地址，用户点确认 | 采用，但只作为 A 的补充（手动入口也预填） |
| C 服务器列表内置一项 | 内置地址作为列表顶部固定一项 | 未采用。比 A 多一次点击，且首屏仍停留在选择界面 |
| D 做成应用内配置项 | 设置里可改默认地址 | 未采用。本次只固定一个地址，不引入多余配置项 |

### 实现细节

- SDK 的 `AddressCandidateHelper` 对以 `http://`、`https://` 开头的输入直接按 URL 解析，再补充协议与默认端口候选，因此 `http://hare.fe.go` 无需额外适配。
- App 允许明文流量（`usesCleartextTraffic="true"` 与 `res/xml/network_security_config.xml`），`http://` 可用，实测投影仪与模拟器都能访问 `hare.fe.go`（192.168.55.12）。
- `versionCode` 仍是 `maxOf(getVersionCode(versionName), 200_100)`，与 v0.1 相同，`adb install -r` 可直接覆盖安装，无需调整版本号逻辑。
- 失败提示复用已有的 `server_connection_failed_candidates` 文案与 `RecommendedServerIssue.getSummary()` 摘要方法，与官方「发现服务器失败」的提示格式保持一致。
